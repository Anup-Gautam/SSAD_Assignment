Each row is one acceptance criterion from `spec.md`, followed by extra rows for gap-checklist categories those criteria do not already cover. Expected numbers are computed from the spec text. Calls use `contracts.md`. A reload is `store.load()` after the write, which is the read the page performs on load.

## Spec gaps

These are listed and not decided here.

### Requirements with no acceptance criterion

- **NFR-006 Standalone operation.** No scenario checks that Canvas, Google Calendar, email, or another external system is absent.
- **NFR-007 Single-student scope.** No scenario checks that there is one student or that accounts are absent.
- **NFR-008 Browser-accessible web UI.** The scenarios assume pages. No criterion's id is mapped to NFR-008, and none checks the browser delivery medium.

NFR-001, NFR-002, NFR-003, NFR-004, NFR-005, and NFR-009 are exercised by the criterion rows above. Every functional requirement FR-001 through FR-008 has at least one acceptance criterion in the spec's traceability table.

### Acceptance criteria with no requirement

None. AC-001 through AC-012 each name functional requirements in `spec.md`.

### Requirement clauses with no scenario

The requirement has other criteria. The clause itself has no scenario. This plan does not rewrite the spec to add criteria.

- **FR-001** says the student can edit courses. No acceptance criterion changes a course name. `updateCourse` is the entry point.
- **FR-003** and Operational Rule 7 say the student can remove a study session. No acceptance criterion deletes one. `extra-delete-session` probes the clause; it does not add a spec id.
- **Operational Rule 1** says required values must be provided before save. No acceptance criterion omits a required value. `extra-missing-deadline` probes that sentence.
- **Operational Rule 6** says dashboard totals count assignments, not subtasks. AC-009's setup has no subtasks. `extra-subtasks-not-counted` probes that sentence.
- **Operational Rule 2** says `Overdue` is an indicator, not an editable status. No acceptance criterion tries to save that status. The AC-008 outside case probes it.
- **FR-004** says rescheduled sessions are checked before save. AC-005 only creates. `extra-reschedule-conflict` probes the reschedule side.
- **No requirement states which error wins when one request breaks two rules.** `extra-precedence` adds no call and does not pick a winner. The contract records a check order so an implementation has one place to follow; that order is not a new spec rule and is not given an acceptance-criterion id.

## Review

- AC-011: 60 + 30 = 90 planned, 45 + 30 = 75 actual, 75 minus 90 = -15. That is 15 minutes less than planned.
- AC-009: 1 completed and 2 remaining, and 1 + 2 = 3.
- AC-010: the spec rejects a nonpositive duration. 1 is the smallest positive whole minute in these cases. 0 and -1 are not greater than zero.
- AC-005 and AC-006: overlap uses a strict "before" test on both ends, so 19:00 against an end of 19:00 is not an overlap. 18:30-19:30 and 18:59-19:30 are overlaps. 19:00-18:00 and 21:00-21:00 do not have an end after the start.
- AC-007: Essay's deadline is before the clock, Lab's is after, Quiz is completed so it is not overdue, and a deadline equal to the clock is not earlier.
- The spec gaps above are unresolved.
